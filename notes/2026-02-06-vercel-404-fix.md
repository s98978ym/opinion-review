# Vercel 404 NOT_FOUND エラー修正

## 日付
2026-02-06

## 事象
Vercel にデプロイした際、トップページが 404 NOT_FOUND を返す。

## 直接原因
`src/app/page.tsx`, `src/app/login/page.tsx`, `src/app/(app)/layout.tsx` が
`import { auth } from "@/lib/auth"` で `auth()` を直接呼び出していた。
`auth()` は内部で Prisma Client → PostgreSQL に接続する。
Vercel 上で DB が未設定（または接続不可）の場合、`auth()` が例外を投げ、
Server Component のレンダリングが失敗 → Next.js が 404 を返していた。

## 根本原因
**暗黙の依存チェーン問題**。`auth()` が Prisma を経由して DB に依存していることが、
呼び出し元のコードからは見えない。この同じパターンは以前にも発生していた:

| # | 呼び出し元 | 依存先 | 壊れた理由 |
|---|-----------|-------|-----------|
| 1 | middleware | auth() → crypto | Edge Runtime に Node.js crypto がない |
| 2 | page.tsx | auth() → Prisma → DB | DB 未接続 |
| 3 | login/page.tsx | auth() → Prisma → DB | DB 未接続 |

3回とも「`auth()` の暗黙の依存が実行環境で解決できない」という同一構造。

## 修正内容

### 変更ファイル
- `src/app/page.tsx` — auth() を try-catch + dynamic import でラップ
- `src/app/login/page.tsx` — 同上。redirect() の re-throw パターンも追加
- `src/app/(app)/layout.tsx` — 同上。認証失敗時は /login にリダイレクト

### 新規ファイル
- `src/app/not-found.tsx` — カスタム 404 ページ（日本語）
- `src/app/error.tsx` — グローバルエラーバウンダリ（リトライボタン付き）

### コミット
`665cba9` fix: resilient auth handling and error pages for Vercel deployment

## 導出ルール（CLAUDE.md に反映済み）
1. **R1**: インフラ依存関数はレンダリングパスで直接呼ばない（try-catch + dynamic import）
2. **R2**: redirect() は throw で動作する — catch 内で飲み込まない（digest チェック）
3. **R3**: error.tsx と not-found.tsx はスキャフォルディング時に作る
4. **R4**: 暗黙の依存チェーンに注意する（関数の依存先を確認してから呼ぶ）

## 追加修正（同日・プラットフォーム 404 継続）

前回の修正後もVercelプラットフォームレベルの404が継続。
調査の結果、アプリコードの問題ではなく、ビルド/ランタイム環境の問題を特定。

### 原因（3層）
1. **middleware.ts 非推奨**: Next.js 16 で `proxy.ts` に移行が必要。
   Vercel のルーティング層が非推奨の middleware を正しく処理できない可能性。
2. **Prisma binary targets 未指定**: ビルド環境(native)とVercelランタイム(rhel-openssl-3.0.x)の
   バイナリ不一致で Prisma が起動できず、ランタイムエラー → 404 にマスクされる。
3. **DATABASE_URL 未設定でモジュール読み込み失敗**: `new PrismaClient()` がモジュールレベルで
   実行され、環境変数がないと import 自体が失敗する。

### 修正内容
- `src/middleware.ts` → `src/proxy.ts` にリネーム（export function名も変更）
- `prisma/schema.prisma` に `binaryTargets = ["native", "rhel-openssl-3.0.x"]` 追加
- `src/lib/prisma.ts` に Proxy パターン導入（DATABASE_URL がなくてもモジュール読み込み成功）

### コミット
- `665cba9` fix: resilient auth handling and error pages for Vercel deployment
- `8618f1c` fix: resolve Vercel platform 404 - proxy migration, Prisma targets, resilient DB init

### 追加ルール（CLAUDE.md に反映済み）
5. **R5**: Vercel デプロイ時のランタイム環境差異に対応する（binaryTargets）
6. **R6**: Next.js 16 では middleware.ts を proxy.ts にリネームする
7. **R7**: モジュールレベルのインスタンス生成は環境変数の存在を前提にしない（Proxy パターン）

## 教訓
- 「動いていること」と「正しいこと」は違う。ローカルでは DB があるから動くが、
  Vercel の初回デプロイでは DB がない可能性がある。
- 同じ構造の問題が3回発生したら、それはバグではなくアーキテクチャの欠陥。
  個別修正ではなく、ルールとして定着させる必要がある。
- **ローカルビルド成功 ≠ デプロイ成功**: ビルド環境とランタイム環境の差異
  （OS、ネイティブバイナリ、環境変数）を常に考慮する。
- **Vercel は未処理エラーを 404 にマスクする**: 本当のエラーが隠れるため、
  ランタイムのすべてのモジュール読み込みと初期化を防御的にする必要がある。
